## 1. Общее описание

Настоящий программный продукт представляет собой инструмент командной
строки, предназначенный для построения, анализа и визуализации графа
зависимостей пакетов менеджера пакетов **Cargo** (экосистема языка
программирования **Rust**).

Инструмент позволяет по имени пакета и его версии построить полный
транзитивный граф зависимостей, выполнить над ним набор базовых и
дополнительных операций и сохранить результат в двух взаимодополняющих
формах:

1. **текстовое описание** графа на языке диаграмм **PlantUML**;
2. **растровое изображение** графа в формате **PNG**.

Приложение реализовано на языке **Python 3** (версия не ниже 3.10).
При разработке **не использовались сторонние библиотеки** и
**готовые менеджеры пакетов** для получения информации о зависимостях:
все данные извлекаются напрямую из **sparse-индекса Cargo**
(`https://index.crates.io`) средствами стандартной библиотеки Python
(`urllib`, `json`, `zlib`, `struct`). Это соответствует прямому
требованию задания: *«Готовые средства (менеджеры пакетов, библиотеки)
для получения зависимостей использовать нельзя»*.

### 1.1 Ключевые особенности

- **Отсутствие внешних зависимостей.** Для запуска достаточно
  интерпретатора Python; установка пакетов через `pip` не требуется.
- **Итеративные алгоритмы обхода.** Построение графа, поиск циклов и
  вычисление порядка загрузки реализованы **без рекурсии**, на явном
  стеке. Это исключает переполнение стека вызовов на глубоких графах
  (проверено на цепочках длиной более 3000 узлов).
- **Корректная обработка циклических зависимостей.** Обход не
  зависает; каждый цикл фиксируется и выводится в виде
  предупреждения.
- **Поддержка фильтрации.** Пакеты, в имени которых присутствует
  заданная пользователем подстрока, полностью исключаются из анализа
  (вместе с их поддеревом).
- **Режим тестового репозитория.** Помимо работы с реальным
  индексом, инструмент поддерживает работу с локальным файлом
  описания графа. В этом режиме пакеты именуются большими латинскими
  буквами, что соответствует требованиям задания и упрощает
  демонстрацию функциональности.
- **Собственный кодировщик PNG.** Изображение графа формируется
  вручную: пиксели закрашиваются на RGB-холсте, затем сжимаются
  алгоритмом `zlib` и упаковываются в чанки PNG в соответствии со
  спецификацией. Это исключает зависимость от графических библиотек
  (таких как `Pillow`) и внешних утилит.

### 1.2 Назначение и область применения

Инструмент предназначен для:

- учебных и исследовательских задач, связанных с анализом структуры
  зависимостей пакетов;
- демонстрации работы итеративных алгоритмов обхода графа;
- визуального анализа сложных деревьев зависимостей;
- сравнения собственного результата с выводом штатных инструментов
  менеджера пакетов (`cargo tree`, `cargo build -v`).

## 2. Структура репозитория

```
.
├── src/
│   └── main.py              весь исходный код (секции по этапам 1–5)
├── tests/
│   ├── fixtures/            файлы тестовых репозиториев
│   │   ├── repo_basic.txt   базовый граф без циклов
│   │   ├── repo_cycle.txt   граф с циклическими зависимостями
│   │   └── repo_filter.txt  граф для проверки фильтрации
│   ├── test_config.py       этап 1: параметры командной строки
│   ├── test_cargo_index.py  этап 2: sparse-индекс Cargo
│   ├── test_graph.py        этап 3: граф, DFS, фильтр, циклы
│   ├── test_load_order.py   этап 4: порядок загрузки
│   └── test_render.py       этап 5: PlantUML и PNG
├── docs/
│   └── logic.md             сравнение с реальным cargo,
│                            объяснение расхождений
├── run.sh                   скрипт запуска (Linux/macOS)
├── run.bat                  скрипт запуска (Windows)
├── Makefile                 цели сборки и тестирования
├── .gitignore
└── README.md
```

Исходный код организован в виде **единого файла** `src/main.py`,
разделённого на логические секции, соответствующие этапам задания.
Такое решение упрощает навигацию и демонстрацию: каждый этап можно
показать изолированно, не переключаясь между модулями.

> **Примечание.** Если файлы `Makefile` и `docs/logic.md` отсутствуют
> в репозитории — их следует создать. См. разделы 4 и 6 настоящего
> документа: в них описано, что должно быть в этих файлах.

## 3. Функции и настройки

### 3.1 Параметры командной строки

Все настраиваемые параметры задаются через опции командной строки.
Разбор и валидация выполняются функцией `parse_config`.

| Параметр | Обязателен | Назначение |
| --- | --- | --- |
| `--package ИМЯ` | да | имя анализируемого пакета |
| `--version ВЕРСИЯ` | да | версия пакета |
| `--repo-url URL` | * | URL sparse-индекса (например, `https://index.crates.io`) |
| `--test-repo ПУТЬ` | * | путь к файлу тестового репозитория |
| `--test-mode` | * | включить режим работы с тестовым репозиторием |
| `--output ФАЙЛ.png` | да | имя файла изображения графа (только `.png`) |
| `--filter ПОДСТРОКА` | нет | не учитывать пакеты с этой подстрокой в имени |
| `--print-config` | нет | вывести все параметры в формате ключ-значение |
| `--direct-deps` | нет | вывести только прямые зависимости (этап 2) |
| `--load-order` | нет | вывести порядок загрузки зависимостей (этап 4) |

\* Обязательно указать **ровно один** источник данных: либо
`--repo-url` (реальный индекс), либо пару `--test-mode` + `--test-repo`
(локальный файл). Одновременное указание обоих источников — ошибка.

### 3.2 Формат файла тестового репозитория

Файл представляет собой текстовый документ, в котором каждая строка
описывает один пакет. Формат строки:

```
ИМЯ_ПАКЕТА : ЗАВИСИМОСТЬ_1, ЗАВИСИМОСТЬ_2, ...
```

Пустые строки и строки, начинающиеся с символа `#`, игнорируются.
Пакет без зависимостей записывается как `ИМЯ :`.

Пример:

```
# Тестовый репозиторий
A : B, C
B : D
C : D, E
D : F
E : F
F :
```

### 3.3 Внутренняя архитектура

| Компонент | Назначение |
| --- | --- |
| `Config` | хранение и валидация параметров командной строки |
| `CargoIndex` | источник зависимостей через sparse-индекс Cargo |
| `TestRepo` | источник зависимостей из локального файла |
| `walk` | итеративный обход графа в глубину (DFS) без рекурсии |
| `find_cycles` | поиск циклов с раскраской вершин (NEW/OPEN/CLOSED) |
| `get_load_order` | вычисление порядка загрузки (пост-порядок обхода) |
| `Canvas` | RGB-холст с операциями рисования |
| `save_png` | собственный кодировщик PNG |

### 3.4 Обработка ошибок

Приложение различает три класса ошибок:

- `ConfigError` — некорректные параметры командной строки;
- `CargoIndexError` — ошибки при обращении к sparse-индексу Cargo;
- `TestRepoError` — ошибки чтения или разбора файла тестового
  репозитория.

Все они перехватываются в точке входа `main()` и выводятся в поток
`stderr` с пояснением на русском языке. Код возврата процесса:
`0` — успешное завершение, `1` — ошибка.

## 4. Команды сборки и запуска тестов

Приложение не требует этапа сборки: это интерпретируемый язык.
Единственное требование — наличие Python 3.10 или новее.

### 4.1 Запуск тестов

Полный набор модульных тестов реализован через стандартный модуль
`unittest`. Тесты разбиты по файлам в соответствии с этапами:

| Файл тестов | Покрываемый этап | Количество тестов |
| --- | --- | --- |
| `test_config.py` | Этап 1. Конфигурация CLI | 9 |
| `test_cargo_index.py` | Этап 2. Спарс-индекс Cargo | 12 |
| `test_graph.py` | Этап 3. Граф, DFS, фильтр, циклы | 11 |
| `test_load_order.py` | Этап 4. Порядок загрузки | 4 |
| `test_render.py` | Этап 5. PlantUML и PNG | 5 |
| **Итого** | | **41 тест** |

Команда для запуска всех тестов:

```bash
make test
```

или напрямую:

```bash
python -m unittest discover -s tests -v
```

Запуск тестов по отдельному этапу:

```bash
python -m unittest tests.test_config -v
python -m unittest tests.test_cargo_index -v
python -m unittest tests.test_graph -v
python -m unittest tests.test_load_order -v
python -m unittest tests.test_render -v
```

### 4.2 Запуск приложения

Linux / macOS:

```bash
./run.sh --package serde --version 1.0.210 \
  --repo-url https://index.crates.io --output out/serde.png
```

Windows:

```bat
run.bat --package serde --version 1.0.210 ^
  --repo-url https://index.crates.io --output out\serde.png
```

Без вспомогательных скриптов:

```bash
python src/main.py --package serde --version 1.0.210 \
  --repo-url https://index.crates.io --output out/serde.png
```

### 4.3 Требуемый `Makefile`

В репозитории должен находиться файл `Makefile` со следующими целями:

```make
run:
	python3 src/main.py $(ARGS)

test:
	python3 -m unittest discover -s tests -v
```

## 5. Примеры использования по этапам

### 5.1 Этап 1. Минимальный прототип с конфигурацией

**Цель этапа:** создать минимальное CLI-приложение и сделать его
настраиваемым.

Вывод всех настраиваемых параметров в формате ключ-значение:

```bash
python src/main.py --print-config \
  --package serde --version 1.0.210 \
  --repo-url https://index.crates.io \
  --output graph.png --filter rand
```

Ожидаемый вывод:

```
package = serde
version = 1.0.210
repo_url = https://index.crates.io
test_repo_path = None
test_mode = False
output_file = graph.png
filter_substring = rand
```

Демонстрация обработки ошибок:

```bash
# Отсутствует имя пакета
python src/main.py --version 1.0.0 --repo-url https://x --output g.png

# Неверное расширение выходного файла
python src/main.py --package a --version 1.0.0 --repo-url https://x --output g.jpg

# Одновременно заданы repo-url и тестовый репозиторий
python src/main.py --package a --version 1.0.0 --repo-url https://x \
  --test-mode --test-repo tests/fixtures/repo_basic.txt --output g.png
```

Каждая из команд завершается кодом возврата `1` и выводит пояснение
в `stderr`.

### 5.2 Этап 2. Сбор данных

**Цель этапа:** реализовать логику получения прямых зависимостей
пакета через sparse-индекс Cargo.

```bash
python src/main.py --package serde --version 1.0.210 \
  --repo-url https://index.crates.io --output out/serde.png --direct-deps

python src/main.py --package clap --version 4.5.23 \
  --repo-url https://index.crates.io --output out/clap.png --direct-deps
```

### 5.3 Этап 3. Основные операции

**Цель этапа:** построить транзитивный граф зависимостей и выполнить
основные операции над ним.

```bash
# Базовый граф
python src/main.py --package A --version 1.0.0 --test-mode \
  --test-repo tests/fixtures/repo_basic.txt --output out/basic.png

# Граф с циклическими зависимостями
python src/main.py --package A --version 1.0.0 --test-mode \
  --test-repo tests/fixtures/repo_cycle.txt --output out/cycle.png

# Граф с фильтрацией (пакеты с подстрокой QUX исключены)
python src/main.py --package A --version 1.0.0 --test-mode \
  --test-repo tests/fixtures/repo_filter.txt --output out/filtered.png \
  --filter QUX
```

### 5.4 Этап 4. Дополнительные операции

**Цель этапа:** вывести порядок загрузки зависимостей для заданного
пакета и сравнить результат с реальным менеджером пакетов.

```bash
# Тестовый репозиторий
python src/main.py --package A --version 1.0.0 --test-mode \
  --test-repo tests/fixtures/repo_basic.txt --output out/basic.png \
  --load-order

# Реальный пакет
python src/main.py --package serde --version 1.0.210 \
  --repo-url https://index.crates.io --output out/serde.png --load-order
```

### 5.5 Этап 5. Визуализация

**Цель этапа:** получить графическое представление графа
зависимостей и сохранить его в двух форматах.

```bash
# Три различных пакета, как требует задание
python src/main.py --package serde --version 1.0.210 \
  --repo-url https://index.crates.io --output out/serde.png
python src/main.py --package clap --version 4.5.23 \
  --repo-url https://index.crates.io --output out/clap.png
python src/main.py --package tokio --version 1.40.0 \
  --repo-url https://index.crates.io --output out/tokio.png
```

Рядом с каждым файлом `*.png` создаётся текстовый файл `*.puml`,
содержащий описание графа на языке диаграмм PlantUML.

## 6. Сравнение с реальным менеджером пакетов

Полная процедура и детальный разбор расхождений приведены в файле
[`docs/logic.md`](docs/logic.md).

Краткая процедура сравнения:

```bash
# Наш инструмент
python src/main.py --package serde --version 1.0.210 \
  --repo-url https://index.crates.io --output out/serde.png --load-order

# Штатный менеджер пакетов
cargo new cargo-demo && cd cargo-demo
cargo add serde@1.0.210 --features derive
cargo tree -e normal
cargo build -v 2>&1 | grep Compiling
```

Состав графа и топология совпадают: `serde` → `serde_derive` →
(`proc-macro2`, `quote`, `syn`) + `unicode-ident`. Зависимости
компилируются раньше зависимых пакетов, что подтверждает корректность
вычисленного порядка загрузки.

Возможные расхождения и их причины:

| Наблюдение | Объяснение |
| --- | --- |
| Разные версии транзитивных узлов | Инструмент выбирает **новейшую** версию каждого транзитивного пакета; `cargo` подбирает версию по требованиям из `Cargo.toml` родителя |
| Отличия в составе графа | Инструмент учитывает только `normal`-зависимости без признака `optional`; `cargo` дополнительно разрешает включённые пользователем фичи |
| Платформо-зависимые пакеты | Инструмент не учитывает `target`-условия |
| Порядок загрузки | Инструмент выдаёт пост-порядок DFS; `cargo` компилирует пакеты параллельно |

> **Требование к файлу `docs/logic.md`.** Если он отсутствует, его
> необходимо создать. Содержание: полный лог сравнения
> `cargo tree -e normal` и вывода инструмента для пакета
> `serde 1.0.210`, а также разбор всех расхождений из таблицы выше.

## 7. Соответствие техническому заданию

| Требование ТЗ | Реализация |
| --- | --- |
| Без сторонних менеджеров и библиотек | Используется только стандартная библиотека Python |
| DFS без рекурсии | Функции `walk`, `visit_for_cycles`, `get_load_order` |
| Обработка циклических зависимостей | Функция `find_cycles`, состояния NEW/OPEN/CLOSED |
| Учёт максимальной глубины | В вариант №22 не входит |
| Фильтрация по подстроке | Функция `is_filtered`, параметр `--filter` |
| Режим тестового репозитория | Класс `TestRepo`, формат `A : B, C` |
| Учёт версии пакета | Обязателен для корня, для транзитивных узлов — новейшая |
| Формирование PlantUML | Функция `build_plantuml`, маркеры `@startuml` / `@enduml` |
| Формирование PNG | Собственный кодировщик `save_png` |
| Демонстрация на трёх пакетах | `serde`, `clap`, `tokio` |

## 8. Ограничения

Следует учитывать, что инструмент читает **sparse-индекс Cargo**, а не
файл `Cargo.toml` конкретного проекта. По этой причине не
учитываются:

- точные требования версий, указанные в `Cargo.toml` родителя;
- включённые пользователем фичи пакетов;
- `target`-условия (платформо-зависимые зависимости);
- секции `[patch]` и `[replace]`.

Все транзитивные зависимости берутся в **новейшей** версии
(см. `docs/logic.md`). Рассматриваются только `normal`-зависимости
без признака `optional`.
